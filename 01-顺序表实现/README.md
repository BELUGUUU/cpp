# 01 顺序表实现 —— 单词检查(Ⅰ)

> 课程设计 OJ（cid=3775）问题 K：单词检查·顺序表实现。拼写检查器系列的第一版。

## 题目

维护一个字典（n ≤ 500000 个单词，词长 L ≤ 15），再给出 m ≤ 200 个待检测单词。对每个待检测单词 w：

- w 在字典中 → 输出 `w is correct`；
- 否则输出所有与 w 恰好差**一次编辑**（插入 / 删除 / 替换一个字符）的字典词，作为修改建议，**按字典中出现先后次序**排列。

两段输入各以 `#` 结束（先字典，后待查表）。

## 思路

- 顺序表（数组）按输入顺序保存字典。
- 对每个待查词 w 从前往后顺序扫描字典：`oneEditAway` 判定 a、b 是否恰好差一次编辑——长度差超过 1 直接排除，同长度双指针找替换位、差 1 双指针找插入/删除位。
- 从前往后扫描，天然满足"按字典出现先后次序输出"的要求。

## 复杂度

- 预处理 O(n)；单次查询 O(n·L)；m 次查询共 **O(m·n·L)**（最坏 1.5×10⁹ 次字符比较）。
- 这正是后续引入 BST（`02`）和哈希（`03`）做同一道题的动机——三种结构做复杂度对比。
