# 04-03 复杂度对比实验 —— 线性表 R/D 操作

> 四种 R/D 实现的性能对比实验，验证"逆转标志"设计的必要性。

## 实验设置

- 规模 n 与操作串长度 |S| = 4n，操作串组成 80% `R` + 20% `D`（D 不超过 n，避免提前 error）。
- 对比四种实现：

| 代号 | 实现 |
|---|---|
| A | 双向链表 + 逆转标志 |
| B | 双向链表 + 物理逆置（每次 R 真的交换指针） |
| C | 顺序表 + 下标窗口 |
| D | 顺序表 + 物理删除（每次 D 真的搬元素） |

四种实现输出逐组比对，**结果完全一致**（正确性对拍）。

## 结果（benchmark_result.txt）

| n | A 双链+标志 | B 双链+物理逆置 | C 顺序+窗口 | D 顺序+物理删除 |
|---|---|---|---|---|
| 2000 | 0.10 s | 8.17 s | 0.02 s | 0.04 s |
| 4000 | 0.19 s | 43.49 s | 0.04 s | 2.41 s |
| 8000 | 0.36 s | 194.87 s | 0.07 s | 11.69 s |
| 12000 | 0.52 s | 478.57 s | 0.09 s | 27.16 s |

增长倍数（n 从 4000 → 12000，规模 ×3）：A 2.8 倍、C 2.3 倍（**线性**，应 ≈3）；B 11.0 倍、D 11.3 倍（**二次**，应 ≈9）。

## 结论

外推到 OJ 上限 n = |S| = 10⁵（再放大 8 倍规模），B/D 需要约 10¹⁰ 次基本操作，而 1 秒大约只能承受 10⁸~10⁹ 次——必然 TLE。这就是必须用「逆转标志」而不是真逆置的原因。

## 文件

| 文件 | 说明 |
|---|---|
| `benchmark.cpp` | 四种实现 + 计时 + 对拍的主程序 |
| `benchmark_result.txt` | 实验原始数据与结论 |

```bash
g++ -O2 -std=c++11 -Wall -o benchmark.exe benchmark.cpp

```
