# 03 哈希实现 —— 单词检查(Ⅲ)

> 课程设计 OJ（cid=3775）问题 M：单词检查·哈希表实现。同一道题的第三个版本，带完整的哈希对比实验。

## 题目

与 `01`/`02` 相同的拼写检查任务，要求**不使用任何泛型库哈希容器**（unordered_map / set / map 全不许用），哈希函数、哈希表、冲突处理全部手写。

## 设计

**哈希函数（三个可互换）：**

| 函数 | 说明 |
|---|---|
| `hashELF` | 题目给出的 UNIX ELF hash，成熟算法，基准 |
| `hashPolynomial` | 自行设计的多项式哈希（BKDR 风格，乘数 131） |
| `hashNaive` | 反面教材：字符直接累加，低位分布极差，仅用于对比实验 |

> ELF 原型用 unsigned long，64 位平台上是 64 位，与"高 4 位回灌"的设计意图不符，统一改用 uint32_t。

**冲突处理（两种都实现，编译期切换）：**

- 链地址法 `ChainHashDict`：int 数组当链表指针，不用 new 结点；
- 线性探测 `ProbeHashDict`：开放定址。表容量取 2 的幂，用 `(h & mask)` 代替取模。

**省内存设计**：字典读进 pool[]，哈希表内部只存"单词在 pool 中的下标"，不存第二份字符串（50 万词省约 16MB），同时该下标即原始出现次序，命中后按下标排序即可还原输出顺序。

**候选词去重**（不依赖集合容器）：三类候选长度互不相同（L−1 / L / L+1），跨类必不重复；同类内部按"连续相同字符只删第一次""插入位置字符等于插入字符时跳过"等规则保证每个候选只生成一次。

## 复杂度

建表 O(n)（期望）；单次查找 O(1+α)；总体 **O(m·L)** 期望。最坏（哈希全冲突）退化为 O(n)。

## 实验结论（benchmark.cpp，详见 benchmark_result.txt）

1. **ELF hash 低位随机性弱**：表容量取 2 的幂、`(h & mask)` 只用低位时，ELF + 线性探测平均探测 336.84 次；补一次终混后降到 1.42——**哈希函数必须与取模方式配套**。
2. 朴素累加哈希 2 万词规模下线性探测平均探测 18934 次，差好哈希 4 个数量级。
3. 链地址法对装填因子不敏感；线性探测在 α→1 时探测长度急剧上升。
